# การวัดผลและพัฒนาโมเดลต่อเนื่อง

## ตัวเลขสามระดับ

1. **ความมั่นใจ 0–100 ต่อชิ้น:** คะแนนโมเดลที่ปรับเทียบด้วย validation โดยนิยามคำตอบถูกว่าประเภทตรงและกรอบทับคำตอบจริง IoU ≥ 0.5 ไม่ใช่การยืนยันว่าภาพปัจจุบันถูกกี่เปอร์เซ็นต์ ค่าเฉลี่ยต่อรอบครอบคลุมเฉพาะรายการที่ตรวจพบ ไม่รวมสิ่งที่ตกหล่น
2. **ผลผู้ใช้รายงาน:** ต้องเลือกคำตอบและยืนยันจำนวนจริง พร้อมยินยอมส่งข้อมูล แยกจากแต้มสะสมและหมายเลขโทรศัพท์ ข้อมูลสมัครใจอาจมีอคติ ไม่ใช่ ground truth ที่ผ่านการตรวจทาน
3. **ผลที่ตรวจทานและ holdout:** ผู้ดูแลตรวจภาพ ตำแหน่ง และประเภทก่อนเปลี่ยนสถานะเป็น reviewed; ชุด holdout ที่ล็อกไว้ใช้ประเมินรุ่นใหม่แยกต่างหาก ห้ามใช้ข้อมูลทดสอบฝึกแล้วอ้างผลเดิม

เพิ่มข้อมูลแล้วอาจแม่นยำน้อยลงได้ หากป้ายกำกับผิด ข้อมูลซ้ำ หรือไม่ตรงบริบท จึงไม่มีการฝึกหรือเผยแพร่อัตโนมัติจากคำทำนายของโมเดลเอง

## กระบวนการ

วิเคราะห์บนอุปกรณ์ → ผู้ใช้ตรวจผล → ยินยอมส่ง metadata → เลือกยินยอมแนบภาพแยกต่างหาก → pending → ผู้ดูแลตรวจภาพและแก้กรอบ/ประเภท → reviewed/rejected → ส่งออกเฉพาะ reviewed → ฝึก candidate → เปรียบเทียบ holdout เดิมและชุดใหม่ → ตรวจ browser → เผยแพร่รุ่นที่ผ่านเกณฑ์

ภาพแนบลดขนาดเป็น JPEG ไม่เกิน 1,024px และตัด EXIF ผ่าน canvas เก็บใน R2 ส่วนตัว ไม่มี URL สาธารณะ ข้อมูลประเมินไม่ผูกกับสมาชิก ไม่ส่งเบอร์โทรพร้อม feedback ผู้ใช้ลบรายการที่เก็บรหัสลบบนอุปกรณ์ได้ ห้ามใช้ภาพบุคคลหรือข้อมูลส่วนตัวโดยไม่มีสิทธิ์

## เครื่องมือผู้ดูแล

กำหนด `REVIEW_ADMIN_SECRET` ผ่าน environment ของเครื่องมือที่เชื่อถือได้ให้ตรง runtime ห้ามใส่ค่าใน command history, Git หรือ frontend ไม่ใช่ PHONE_HASH_SECRET และไม่ควรหมุน PHONE_HASH_SECRET เพื่อจัดการรีวิว

```sh
node scripts/review-feedback.mjs export ml/data/review-queue
# เปิดภาพ ตรวจทุกกรอบ/ประเภท แก้ review-decisions.json และตั้ง reviewed/rejected ทีละรายการ
node scripts/review-feedback.mjs publish ml/data/review-queue/review-decisions.json
node scripts/review-feedback.mjs dataset ml/data/reviewed
python ml/train_detector.py --reviewed ml/data/reviewed/annotations.json --version wastevision-ssdlite-v4-candidate
```

คำสั่ง publish หมายถึงส่งผลตรวจทาน ไม่ได้เผยแพร่เว็บไซต์ ข้อมูล pending และรายการไม่มีภาพไม่ถูกส่งออกเป็นชุดฝึก เครื่องมือไม่อนุมัติคำตอบที่โมเดลคาดการณ์ไว้ให้เอง ข้อมูลและภาพใน ml/data ถูก ignore จาก Git

ก่อนเริ่มฝึกรุ่นต่อไปเก็บ weights/report ของรุ่นปัจจุบันบน branch/tag และเปลี่ยน model_version เพื่อไม่รวมสถิติข้ามรุ่น วัด precision/recall, mAP50–95, count MAE/exact-match, calibration ECE/Brier และ recall ของแต่ละกลุ่มอันตราย การตรวจไม่พบแบตเตอรี่ไม่ใช่หลักฐานว่าไม่มีแบตเตอรี่

การตรวจทานไม่ทำให้เป็น Thai field test โดยอัตโนมัติ ต้องทราบแหล่งภาพและยืนยันวัตถุจริงด้วย ชุด TACO กับ E-Waste ต่างประเทศไม่ใช่หลักฐานใช้งานหน้างานไทย
