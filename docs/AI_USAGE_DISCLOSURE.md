# การเปิดเผยการใช้ AI ช่วยพัฒนาโครงงาน

เอกสารเริ่มต้นตามแนวทาง CE564 หน้า 11 ผู้เรียนต้องเติมผลตรวจและความเข้าใจของตนเองก่อนส่ง ไม่ใช่หลักฐานว่าสมาชิกทุกคนอธิบายโค้ดหรือทำการทดลองเองแล้ว

## เครื่องมือและบทบาท

ใช้ OpenAI Codex ช่วยวิเคราะห์ความต้องการ ออกแบบและเขียนโค้ดเว็บ/Worker สคริปต์ข้อมูลและโมเดล ชุดทดสอบ เอกสาร และวิเคราะห์ syllabus ผู้ใช้เสนอเป้าหมายและอนุมัติขอบเขต เช่น จำแนกหลายชิ้น คำแนะนำถัง บัตร และการเชื่อมเนื้อหาวิชา

แนวทางคำสั่งรอบนี้: เทียบผลลัพธ์การเรียนรู้กับระบบที่มี → เสนอ baseline/ข้อมูลไทย/การค้นคำแนะนำ/RAG/local-vs-API → ผู้ใช้อนุมัติให้พัฒนาและปรับ README เพื่อทำสไลด์ → สร้างการทดลองที่ทำซ้ำได้และรายงานข้อจำกัด ไม่ใช่คำสั่งให้รับรองว่าระบบถูกต้องทั้งหมด

## การตรวจผลที่ทำผ่านเครื่องมือ

- รันชุดทดสอบอัตโนมัติ โค้ด API และการป้องกันข้อมูลข้าม split
- ฝึกและวัด baseline จากไฟล์ภาพจริง โดยแยก validation/test
- วัด retrieval ด้วยคำถาม regression ที่ระบุแหล่งและขอบเขต
- build และตรวจ API ของเวอร์ชันเผยแพร่ แยกจากการทดสอบหน้าจอและอุปกรณ์จริง
- ดูรายงานผลและข้อจำกัดใน README และ `ml/results/` ไม่มีการถือว่าคำตอบ AI เป็นผลทดลองหากไม่ได้รัน

## สิ่งที่ผู้เรียนแต่ละคนควรทำและบันทึกเองก่อนส่ง

| รายการ | หลักฐานที่ผู้เรียนเติม |
| --- | --- |
| ส่วนที่รับผิดชอบ/แก้ไขเอง | ชื่อ ไฟล์ commit และเหตุผล |
| ความเข้าใจโมเดล | อธิบาย preprocessing, transfer learning, loss/optimizer, split และ metrics |
| ตรวจคำตอบและแหล่งอ้างอิง | รายการที่ตรวจ พบข้อผิดพลาดอะไร แก้อย่างไร |
| ทำซ้ำการทดลอง | คำสั่ง environment ผลจริง และความต่างจากรายงาน |
| ข้อจำกัด/จริยธรรม | สิทธิ์ข้อมูล อคติ ความเป็นส่วนตัว และสิ่งที่ยังทดสอบไม่ครบ |

อย่าใส่ prompt history ที่มี secrets เบอร์โทร หรือข้อมูลบุคคลลงรายงาน ใช้คำอธิบายแนวทางและตัวอย่างที่ลบข้อมูลแล้ว เอกสารนี้ไม่แทนการเปิดเผยการใช้เครื่องมืออื่นของสมาชิกแต่ละคน
