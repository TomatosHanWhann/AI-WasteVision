# แนวทางตรวจและประเมิน

## อัตโนมัติ

`npm test` ตรวจ API กับฐานข้อมูล SQLite จริงแบบ in-memory: consent, origin, session, บัตรเบอร์เดิม, ticket คนละบัตร, ภาพซ้ำ, ขีดจำกัดรายวัน และ 999→1,000 ระดับ A รวมกฎวัสดุและ HMAC ไม่ใช้เบอร์บุคคลหรือส่ง SMS

`npm run build` ตรวจ Worker และ assets ทั้งสอง HTML entry; `python ml/check_model.py` ตรวจ hash, labels, output shape และ metadata/report; `ml/train.py` ประเมิน test ผ่าน ONNX export จริง

## ตรวจหน้าเว็บ

1. ตรวจ about/presentation และ guide ไม่มีรายละเอียดภายในทีม ใช้ข้อความทางการ
2. วิเคราะห์ตัวอย่างทั้งหกวัสดุและภาพนอกขอบเขต อ่านผลจริงแม้ไม่ถูกต้อง ภาพตัวอย่างต้องไม่เพิ่มแต้ม
3. เลือกภาพหรือกล้องหนึ่งชิ้นต่อภาพ ตรวจแนวตั้ง/นอน ไฟล์เสีย/ใหญ่/ผิดชนิด และปฏิเสธสิทธิ์
4. เปลี่ยนสภาพสะอาด เปื้อน และอันตราย ตรวจคำแนะนำและสิทธิ์ยืนยัน
5. ใช้เบอร์ fixture สังเคราะห์ เปิดบัตร ยืนยันภาพที่เข้าเงื่อนไข ตรวจยอด +1 ภาพเดิมไม่เพิ่มซ้ำ ปิดแล้วเปิดบัตรเดิมยอดคงอยู่
6. บัตรสาธิต A มีป้ายกำกับและไม่เปลี่ยนยอดจริง ห้ามเติม 1,000 แต้มใน production เพื่อถ่ายภาพ
7. ตรวจมือถือ 390px, focus/keyboard, zoom, reduced motion และ QR

## การศึกษาภาคสนาม

กันวัตถุใหม่ไม่เคยฝึกอย่างน้อย 8 ชิ้นต่อหกวัสดุ (48 ชิ้น) และนอกขอบเขต 10 ชิ้น ปรับจากแผนห้าวัสดุเดิมเพราะเพิ่มแก้ว ถ่ายหลายแสง/ฉากหลังโดยคงรหัสวัตถุเดียวกัน ห้ามนำ test กลับไปฝึกแล้วอ้างผลเดิมว่าเป็น holdout

บันทึก truth จากการตรวจวัสดุจริง ไม่อิง AI แยกภาพ catalog ออกจากภาพใช้แล้ว รายงาน confusion matrix, precision/recall/F1, macro F1, known coverage, unknown rejection และ median/p95 latency รวมภาพที่ไม่แน่ใจด้วย ใช้ `field-test-template.csv` เป็นแบบบันทึกภายนอก ไม่เก็บตัวตนในชุดวิจัย

การทดลองผู้ใช้ประมาณ 10 คนยังต้องเก็บจริง เปรียบเทียบการคัดแยกเองกับการใช้ระบบโดยสลับลำดับและวัตถุเทียบเคียงกัน ความพึงพอใจและประโยชน์ต้องอ้างข้อมูลที่เก็บ ไม่อนุมานจากแต้มสะสม
